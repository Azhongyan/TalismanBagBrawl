# V0.4-FormalItemCombatCausalAttributionFeedback01 Task Contract

## 1. Outcome

在 Unified 正式实时战斗中，每一次被 Battle 接受的 Item 伤害都形成一条可读、连续、可归因的纯视觉表现链：

`精确来源 Item/Card/Artwork 蓄势 -> 短促来源到目标的视觉桥 -> 精确目标 Hit/Impact/HP 变化 -> 普通实际伤害数字`。

玩家先在 ItemDetail popup 中了解某件道具的基础伤害、冷却/触发与激活条件；关闭详情进入战斗后，必须只凭来源 Artwork/位置/轮廓/颜色/效果运动 -> 目标反应 -> 普通数字的连续动作，推断“这次伤害来自哪件道具”。在 1-2 同时存在 I001/I002 时，不阅读说明文字或 Battle log 也必须能区分两者。表现只消费 Battle 已接受的不可变 cue，不计算或改变伤害。

本包与 Item 品阶描边/泛光、未来 Formation 完全分离，不恢复旧卡片/硬方块弹道、粗糙火焰 Impact 或已否定的棋盘格阵法。

禁止把战斗做成文字游戏：实时表现不得出现来源名称/ID文字 badge、`I001 -82` 一类来源归因浮字、“直接伤害/由谁造成/公式”说明句或每击强制解释日志。普通纯数字 `-82` 可以保留，但不能承担全部因果表达。

## 9. Required Behavior

1. `ItemTriggerScheduled/Accepted` 携带精确 source/target -> 可见 Card 在原位蓄势/脉冲；Card 不可见时使用 authored 无文字 Artwork/icon/silhouette proxy。
2. 来源 Artwork/proxy -> 短促、清晰、非卡片 projectile 的软发光因果桥 -> 权威 target anchor；多敌人不得串目标。
3. 同一 accepted event 的 `HitAccepted/Impact/DamageFloatPayload` -> 复用 target Hit/Impact/audio，并只显示 cue 的普通实际 `appliedDamage` 数字。
4. `requestedDamage != appliedDamage` -> 本包不解释差值、不补算；ItemDetail 负责静态能力说明，实时只显示真实结果。
5. Card 不可见/inactive -> 无文字 source proxy 必须保留来源 Artwork/轮廓可辨识性；不得退化为文字 badge。
6. I001-only -> 玩家通过连续视觉动作看出 I001 触发；I001+I002 -> 相邻/交错 cue 依靠 Artwork/起点/style/运动语言区分，不读文字或 log 也不混淆。
7. duplicate/stale/zero-applied cue -> 沿用 monotonic/dedupe 规则，不重复播放，不伪造正伤害浮字；零结果按现有正式语义 fail-soft。
8. Reset/Stage change/Death/Disable/Reload -> 所有 source visual、ribbon、Impact、float 与 audio 复位幂等，无残留、无对象增长、无 MissingReference。
9. 所有 Graphic `raycast=false`；不得修改 authored RectTransform、Battle UI 布局、Card 几何或目标选择。
10. Runtime 只驱动 authored/poolable carrier；禁止 `new GameObject`、runtime final hierarchy、`GameObject.Find`、RuntimeInitialize bootstrap 或 Item/Battle truth 推断。
11. Player-owned Item 的 `HitAccepted/ActorHpChanged/DamageFloatPayload/ActorDefeated` 可见呈现必须按 `acceptedApplicationEventId` 进入有界 pending queue，在 causal ribbon 抵达后依 cue sequence 释放；不得在 ribbon 启动的同一帧提前 Hit/Impact/浮字/Death。
12. pending 期间只保留上一帧已呈现的 HP/Death 外观；不得改写、克隆为第二套 Battle 真相，不得阻止后续 Battle tick。Enemy-owned Hit 保持既有即时反馈，不得被 Item 因果队列误延迟。

## 10. Failure / Edge Cases

- 缺 source Card/artwork/profile style：不得用来源文字替代；Battle 继续运行，记录一次简洁诊断并清理该次视觉桥。本包不能以 generic 数字浮字冒充完整归因。
- 缺 target anchor：不自行选择目标；记录一次简洁诊断并清理该事件表现。
- cue 乱序/重复：以 monotonic cue identity 与 accepted event identity 去重/关联，不回放 stale 事件。
- 连续事件：source visual/ribbon 使用有界池，普通 float 复用既有池；不得无限 Instantiate 或互相覆盖到不可读。
- 同一帧多个 Item accepted event：按 cue sequence 保持确定顺序并使用有界 pending queue；不得合并成一个无法归因的 Impact，也不得丢失任何真实数字。
- ribbon/target 在 pending 期间失效：清理该次视觉缓存并记录一次诊断；Battle 继续，不把 stale Hit/Death 播放到新波次。
- Domain Reload/半初始化/已销毁 Unity 对象：null/destroy guard，清理幂等。
- Profile/字体/材质/音频缺失：VFX/audio fail-soft，但来源 ID 与实际数字文本不得消失；不得阻塞 Battle。
