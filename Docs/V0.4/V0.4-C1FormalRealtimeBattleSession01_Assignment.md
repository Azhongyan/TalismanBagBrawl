## 8. Required Runtime Behavior

1. Start only from valid `CAMPAIGN_NORMAL_LV1` 1-1 or 1-2 launch/context plus
   accepted formal Item battle input.
2. Create a live session, not an immediate final result and not a replay of a
   precomputed ledger.
3. Use integer millisecond battle time. Accepted due times must include:
   - lit Item cooldowns at 2000ms intervals from Item facts;
   - enemy basic first at 4500ms, then every 4500ms from Enemy facts.
4. Advance only through explicit lifecycle methods such as:
   - `TryStart(...)`
   - `TryPause(...)`
   - `TryResume(...)`
   - `TryAdvanceBy(deltaMs, out tickResult)`
   - `TryAdvanceTo(targetBattleTimeMs, out tickResult)`
   - `TryReset(...)`
   - `TryGetSnapshot(...)`
5. Same-tick order remains `player_then_enemy`.
6. Actor target order remains stable Enemy actor row order.
7. One accepted Item application may carry over overkill to the next legal
   actor, matching the accepted oracle.
8. Enemy basic wave is one player-damage application per wave for the encounter.
9. I002 unlit schedules no accepted damage and must emit diagnostic/not
   executed state, not a zero-damage accepted event.
10. Terminal must occur only after advancing through due events. A newly started
    session must expose live non-terminal state before terminal.
11. Session terminal result must match the accepted oracle exactly:
    - 1-1: `16000ms / enemyApplications=3 / playerHp=76`.
    - 1-2 weak: `48000ms / enemyApplications=10 / playerHp=20`.
    - 1-2 target: `36000ms / enemyApplications=7 / playerHp=44`.
12. Terminal result may project `BattleResultSnapshot`, but it must keep:
    - `shouldWriteSave=false`
    - `shouldGrantReward=false`
13. Reset/unbind invalidates stale pending events, stale ticks, old item input,
    and old presentation cues.
