# V0.4-C1Lv1StarterItemBaseline01

## 1. Outcome

Create the single, context-scoped Item data carrier for the accepted `CAMPAIGN_NORMAL_LV1` starter baseline.  It must be the only Item-side authority for these two approved Item versions:

| context | baseItemId | rarityVersionKey | directDamage | cooldownSeconds | lighting requirement |
|---|---|---|---:|---:|---|
| `CAMPAIGN_NORMAL_LV1` | `I001` | `I001@white` | 82 | 2 | `LIT_REQUIRED` |
| `CAMPAIGN_NORMAL_LV1` | `I002` | `I002@white` | 28 | 2 | `LIT_REQUIRED` |

Expose a read-only Item Fact Projection that Reward can consume later by `baseItemId + rarityVersionKey + profileRevision`.  This package does **not** create, configure, or invoke a Reward.

## 2. Product Context

The already accepted P0 loop is:

`1-1: I031 + I001@white -> first-clear I002@white -> player repositions -> 1-2 has a visible consequence.`

Only the simple teaching sentence is in scope: **“已亮才出手”**.  An unlit Item does not operate.  Direct and relay lighting are deliberately equal in this package; do not add relay strength, nian spending, Build, Core, or any extra gameplay rule.

Accepted analysis evidence, not new runtime behavior:

| 1-2 layout | expected outcome |
|---|---|
| legal weak layout: I002 unlit | 48 seconds / 10 enemy attack waves |
| target lit layout: I002 lit | 36 seconds / 7 enemy attack waves |
| I002 direct damage -20% / +20% | 38 sec / 34 sec; the layout difference remains materially visible |

These measurements are recorded only as `designEvidence`; no Battle, Stage, Enemy, Scene, or Reward code may consume them in this package.

## 4. Ownership and Data Contract

Create one new Item-owned, immutable runtime contract in exactly this runtime file:

`Assets/_Game/Scripts/TalismanBag/Items/CampaignBaseline/C1Lv1StarterItemBaseline.cs`

The file may contain the tightly coupled public types required for this one contract, including:

- an explicit campaign-context identifier that accepts only `CAMPAIGN_NORMAL_LV1`;
- an immutable baseline profile with `schemaId`, `campaignContext`, `profileRevision`, `baseItemId`, `rarity`, `rarityVersionKey`, `directDamage`, `cooldownSeconds`, and `lightingRequirement`;
- an immutable `C1Lv1StarterItemFactProjection` with the same Reward-readable stable identity fields plus the source canonical signature;
- a static catalog/provider which is the **only** location containing `82/2` and `28/2`;
- deterministic canonical-signature construction and explicit validation/result errors.

Required fixed identifiers:

```text
Baseline schema: C1Lv1StarterItemBaseline.v1
Projection schema: C1Lv1StarterItemFactProjection.v1
Profile revision: C1LV1_STARTER_ITEM_BASELINE_R1
Context: CAMPAIGN_NORMAL_LV1
Rarity: white only
Lighting requirement: LIT_REQUIRED
```

Requirements:

1. The catalog must expose exactly two rows: `I001@white` and `I002@white`; each identity appears once.
2. The projection must be derived from the baseline row.  It must not be a second hand-authored table of damage/cooldown values.
3. `I031`, unknown Item IDs, unsupported rarities, unsupported contexts, duplicate identities, malformed version keys, and empty required identifiers must fail explicitly with a stable error/result and `projection=null`; never throw an unhandled exception or fall back to a Workbench row.
4. Use existing `ItemInstanceRarity` and the existing Item Catalog only for ordinary-item/identity validation.  Do not alter either existing source.
5. Canonical output must use ordinal sorting, invariant culture, explicit field ordering, and no random/time/global-state input.  Equal calls and reversed input enumeration must produce the same signature and projection values.
6. The contract is an Item Fact Projection for later Reward read-only consumption.  It must not reference Reward, Drop, Battle, Enemy, StageFlow, Inventory, Save, UI, Scene, or Build namespaces/classes.
7. Do not generate an Item instance, spend a seed, create a Roll, mutate a ScriptableObject, or attach the carrier to a GameObject.
8. `designEvidence` may appear only in QA/report evidence.  It must not be a runtime effect field and must not be exposed as an executable Battle rule.
