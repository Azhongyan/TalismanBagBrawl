## 5. Balance Gate

Decision sentence：

> Freeze one discrete source-progress step for I022 and I025: each accepted operator mutates at most one eligible pending action by exactly one source-native action interval, with deterministic target/order and no global turn-to-time conversion.

Authority and maturity：

```text
I022 candidate value: 1 turn / CANDIDATE
I025 candidate value: 1 turn / CANDIDATE
Item descriptors and canonical signatures: AUTHORITATIVE_STATE_ONLY
pending Item trigger / enemy cast due time and interval: AUTHORITATIVE_EXECUTED by Battle
global turn-to-ms or turn-to-seconds ratio: UNKNOWN_OR_CONFLICTED / FORBIDDEN
```

Weak / middle / target：

```text
weak: neither I022 nor I025 active -> 0 progress mutations
middle: exactly one source active and eligible -> exactly 1 progress mutation
target: both sources active with valid conditions -> each operator mutates one distinct eligible action; no fan-out
```

Sensitivity：

- vary source-owned action interval/cadence by `-20% / baseline / +20%`;
- operator count remains one action / one source-native step;
- target ordering, no-duplication and native `turn` identity remain invariant;
- do not tune Item value or invent a global duration.

Allowed knobs：

1. mutation cap fixed at `1 action / 1 step / accepted operator`;
2. target selection fixed to earliest due action, then source stable order, then action stable order.

## 12. Required Behavior

1. Session start binds `itemBattleInputCanonical + arrangementCanonicalSignature`; missing arrangement truth is allowed for legacy no-progress-operator sessions but rejects I022 relation execution.
2. I022 requires exactly one valid relation row for its active source. The row must match the bound input/arrangement canonicals, relation `adjacent_lit_item`, source instance and a sorted unique candidate set.
3. Every I022 candidate target must be a current placed+lit active Item fact, must not be the source itself and must own exactly one future pending `ITEM_TRIGGER` action. Invalid/unknown/duplicate/stale candidates reject the entire event atomically.
4. Battle selects the I022 target; the caller does not. Selection order is earliest `dueBattleTimeMs`, then source stable order, then action stable order.
5. `ADVANCE_ITEM_TRIGGER_PROGRESS_STEP` changes one future pending Item action from `before` to `max(currentBattleTime, before - sourceNativeIntervalMs)`. This is one source trigger progress step, not `turn -> milliseconds` conversion.
6. I025 requires an active accepted source and immutable `target_casting` condition. Battle selects exactly one future pending cast-capable enemy action, ordered by due time, source stable order, then action stable order.
7. The existing `ENEMY_BASIC_WAVE` pending action may be declared cast-progress-capable without changing its damage or cadence. `DELAY_ENEMY_CAST_PROGRESS_STEP` changes one action from `before` to `checked(before + sourceNativeIntervalMs)`.
8. Each operator mutates at most one action and one step per accepted source application. The same event cannot mutate twice; a distinct accepted event may apply a later step if its target remains valid.
9. Preflight target/action existence, canonical bindings, native unit, interval, overflow and lifecycle before live state mutation. Rejected/stale/duplicate input causes no effectState、action due time、application ledger、mutation ledger or cue delta.
10. Accepted execution commits effectState and action reschedule together, then emits exactly one immutable mutation ledger row and one authoritative cue traceable to event、source Item、operator、target action、before/after and canonical signature.
11. Queue processing must not execute an action from a stale materialized due-list after its due time was rescheduled.
12. I022/I025 remain `CANDIDATE`; values stay `1 turn`. No Item number, Enemy number, effect family or descriptor is copied or promoted.
13. Preserve all existing 15/15 descriptor compatibility, exactly five shared families, I002 direct-damage separation, 0/1/2 active filtering, real defeat, lifecycle, reset, refresh and legacy action traces when neither operator applies.

## 13. Failure / Edge Cases

- missing/stale item input or arrangement canonical：reject atomically;
- relation source not active placed+lit or candidate target not active：reject atomically;
- empty/duplicate/self target candidate：reject atomically;
- no future eligible Item trigger / no future cast action：reject without state mutation;
- duplicate event or duplicate relation：idempotent rejection;
- target action executed/rescheduled between preflight and resolve：stale rejection, no partial commit;
- interval `<= 0`、overflow or unsupported action kind/unit：reject；UNKNOWN/UNSUPPORTED never becomes zero;
- pause/reset/terminal/generation mismatch：reject；
- refresh invalidates relation：old relation canonical becomes stale and cannot mutate the new arrangement；
- sensitivity changes source intervals only; operator count/order/cap cannot drift。
