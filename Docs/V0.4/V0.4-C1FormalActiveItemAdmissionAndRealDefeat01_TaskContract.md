### Stage 1-2 admission

  schedules and active facts.

### Realtime terminal authority

- A stage 1-2 live Session must start non-terminal and advance only through its
  scheduled Item and Enemy actions.
- Live HP, actions, target/death state and the event ledger determine victory or
  defeat.
- A deterministic application oracle may remain optional comparison evidence
  for layouts it supports, but it must not gate stage 1-2 start, terminal
  acceptance, victory or defeat.
- Missing or rejected winning-oracle output is not an error for an otherwise
  valid stage 1-2 layout.
- The existing live Session must be able to return an accepted defeat with
  `win=false`, `lose=true`, `shouldWriteSave=false`,
  `shouldGrantReward=false`.
- Preserve existing event order, damage numbers, cooldowns, enemy cadence,
  targeting, dedupe, reset and stale-envelope rejection.
