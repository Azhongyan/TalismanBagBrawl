## 9. Required Behavior

### 9.1 基础轨

唯一基础轨：

`Approach/RunSurrogate -> Ready/Idle -> Attack 或 Skill -> Death -> Exit/Continue`

- RunSurrogate 只使用前倾、轻微身体起伏、地面尘步或背景相对运动；必须集中为可替换表现槽，不能伪装为正式 Run 动画。
- Attack / Skill 通常播放至本段结束，不能因普通连续伤害反复重启。
- Death 是终态，出现后锁定本轮基础轨。
- 动画完成不决定伤害、死亡、掉落或关卡推进。

### 9.2 独立受击层

- 每个 fixture damage event 保留唯一 event identity 和飘字/反馈。
- 普通受击：短闪色、克制位移/压缩、可选轻粒子和声音；不替换当前 Attack / Skill 帧序列。
- HeavyHit：仅显式 fixture qualifier 可触发完整 d1_3 Hit 序列；需要可中断、可恢复，不改变 damage truth。
- 视觉节流只能合并动势，不能丢失或重复事件数字。

### 9.3 横向遭遇循环

- 一条水平战斗带；无摇杆、无手动移动、无自由追逐、无寻路或自由刚体。
- 玩家从左向右自动推进；敌人从右侧进入；双方在固定锚点停下。
- 战斗段约 10–20 秒，至少包含一次 Attack、一次 Skill、数次普通受击 overlay、一次 HeavyHit、一次 Death。
- Death 后播放短促的 presentation-only loot/drop beat；不得授予真实奖励、写 Save 或推进 Campaign。
- 玩家恢复推进并离开，随后自动重置下一轮。
- 允许读取现有玩家 Image 作为 presentation source，但必须使用 runtime proxy / motion carrier；不得写 authored RectTransform、parent、sibling、layout 或 Scene。
- d1_3 actor 第一版只显示一个；不得扩展成 C1 三怪或正式 1-1 roster。

### 9.4 生命周期

- 自动安装仅限目标 BattleSandbox Scene。
- 不创建 Panel、OnGUI、快捷键、隐藏控制条、测试场景或序列化空物体。
- Disable / Enable / Scene unload / Domain reload / 重播清理幂等。
- 每轮结束回到缓存的绝对锚点；不得累计 transform、alpha、sprite 或临时对象漂移。
- 每次重播前清空 owned VFX / float / audio / Sprite wrapper 状态；不得销毁 Resources Texture2D。

## 10. Failure / Edge Cases

- 任一 d1_3 状态缺失：使用明确的最近合法静态帧或 Idle fallback，并记录一次简洁 warning；不得借用其他敌人整套动画。
- 玩家 authored Image / Canvas / Battle area 缺失：fail-closed，恢复已改显示，禁止创建替代正式 UI 层级。
- 重复 fixture cue：按 cue id 去重。
- 普通 damage 与 Attack/Skill 同时发生：受击 overlay 优先显示，但基础轨继续。
- Death 到达：清理普通 hit / HeavyHit 并锁定 Death。
- Unity 或外部 Editor 已占用：先做离线代码；不得启动、终止或清理不属于本包的进程/锁。
