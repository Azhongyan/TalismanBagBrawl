## 8. Cue Consumer Contract

Consume only `C1FormalRealtimeBattleState`, actor snapshots, and `C1FormalRealtimeBattleCue`:

| Cue/state | Presentation result |
|---|---|
| `SESSION_STARTED` / current state | reset all pooled/transient visuals, bind player/enemy snapshots, show initial HP |
| `ACTOR_SPAWN_VISIBLE` | populate the matching stable-order enemy slot from authoritative content/profile identity |
| `TARGET_CHANGED` | move the one target outline to `targetActorId/targetStableOrder`; clear on invalid/defeated |
| `ITEM_TRIGGER_SCHEDULED` | optional restrained wind-up only when exact source item carrier resolves |
| `ITEM_TRIGGER_ACCEPTED` | pulse the exact formal Board/Tray source card resolved from immutable Item roster + serialized card views; no projectile/card travel |
| `ENEMY_ATTACK_SCHEDULED` | telegraph/attack wind-up on the Battle-identified source/eligible actor only |
| `ENEMY_ATTACK_ACCEPTED` | resolve the enemy attack presentation and player-side reaction/audio |
| `HIT_ACCEPTED` | short target-local flash/recoil without owning hit acceptance |
| `PLAYER_HP_CHANGED` | update player HP from authoritative before/after values |
| `ACTOR_HP_CHANGED` | update the matching enemy HP from authoritative before/after values |
| `DAMAGE_FLOAT_PAYLOAD` | spawn one deduped TMP float at the cue's exact receiver using `floatPayload`/accepted event id |
| `ACTOR_DEFEATED` | play Death once, disable target selection for that actor, retain/clear slot only per presentation profile |
| `BATTLE_TERMINAL` | settle transients and leave a stable completed battle presentation; never grant or advance flow |
| pause/resume/reset | pause/resume presentation clocks or perform idempotent reset; never alter Battle clock |

Rules:
- Monotonic `cueId/sequence`; dedupe by cue identity and accepted application identity where present.
- Stale/replayed cues never create a second float, sound, death, source pulse or VFX.
- Presentation may interpolate local visuals but may not delay, acknowledge, block or reorder Battle.
- Missing optional art/audio uses a quiet safe fallback; missing required authored slot fails validation without constructing a runtime replacement hierarchy.
- Resolve `sourceId` through authoritative Formal Item roster (`baseItemId@rarityKey`) and serialized C1 Formal card references; no itemId-style branch or Chinese label parsing.
