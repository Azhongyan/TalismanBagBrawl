## 9. Required Behavior

### 9.1 Immutable completion proof

Add the smallest public immutable completion-proof contract inside the allowed resolver file, plus a public `CreateSession` overload that consumes it. Preserve the existing clean-start `CreateSession(runSessionId, rootSeed)` overload.

The proof carries only:

- exact authority identity;
- exact `productContext`;
- exact `chapterId`;
- a defensive-copied immutable view of `completedStageIds`;
- canonical payload/signature data required for fail-closed validation.

Validation rules:

- `null` proof fails closed at session creation.
- Empty completed set is valid.
- A non-empty completed set must be the unique contiguous prefix of `1-1` through `1-5` in exact order.
- Wrong authority, context, chapter, duplicate, unknown, malformed, gapped, reordered, noncanonical, or tampered proof fails closed.
- Validation must not sort away a gap, duplicate, unknown value, or order mismatch.
- All exposed collection units are immutable defensive copies.
- The released result must report the exact public type/member inventory and exact canonical/signature semantics.

### 9.2 Session-local semantics

1. Every new Reward session starts with empty accepted opportunities, empty recent-2 history, `acceptedDropOrdinal` beginning at 1, and `nextExpectedClearSequence` beginning at 1.
2. Persisted completion count must never offset Reward sequence, ordinal, accepted opportunities, or recent history.
3. Proof membership seeds only campaign completion knowledge:
   - proof-completed eligible stage: legal replay using `RepeatChallengeOnline`;
   - a stage first-cleared earlier in this in-memory session: later legal replay using `RepeatChallengeOnline`;
   - first not-yet-completed stage in the exact progression: legal `FirstClearOnline`;
   - any uncleared stage ahead of the first gap: atomic reject.
4. Replay of any proof-completed `1-1` through `1-5` stage is accepted only at the next session-local clear sequence.
5. A byte-identical retry of an accepted `StageClearFact` remains idempotent: `isNewGrant=false`, zero duplicate grant, byte-identical prior result, and no state/history mutation.
6. Same sequence with conflicting identity and same ID with conflicting bytes remain atomic rejects.
7. Every accepted new legal clear or replay is a distinct opportunity and grants one direct random ordinary Item.
8. Recent-2 remains process/session-local and continuous only within the session. Recreating a session with the same proof restores no accepted opportunities and no recent history.
9. Existing pool15, equal/no-choice/no-drop, sixth-plus replay, claim/dedupe, materialization, numbers, weights, Item truth, and RNG algorithm remain unchanged.
10. Snapshot canonical validation binds the immutable completion proof and the effective completion semantics without becoming a second persistence owner.

## 10. Failure / Edge Cases

- Missing or invalid proof: fail closed before a session is created.
- Invalid/stale/duplicate/conflicting `StageClearFact`: preserve existing strict correlation and atomicity; no state, history, completion, claim, or grant mutation.
- Gapped completion: reject; do not infer or sort.
- Reload/restart: only the validated completion-only proof may seed completion knowledge. Reward opportunities, recent history, result identity, RNG position, and inventory/session state are never restored by this package.
- Any need to edit a protected or non-whitelisted source, alter player-visible semantics, or cross into Mainline/WorldMap/Save/UI is an exact blocker.
